## 省流

> TCP 在不可靠的 IP 网络之上，用一套端到端机制近似提供**可靠、有序、字节流**传输。核心手段包括：校验和发现差错，序号与确认跟踪字节，超时重传与快速重传补齐丢失，滑动窗口做流量控制，以及拥塞控制避免过度注入网络。
>
> “可靠”指：在连接未中断、重传未放弃的前提下，接收方按序向上层交付无重复的字节流；它不能消灭所有故障，例如对端崩溃或网络长期中断时，连接仍可能失败。拥塞控制主要保护网络整体，不单是“别把对端缓冲区写爆”——后者由通告窗口完成。

## 主要机制

### 1. 校验和

段中携带校验和，接收方校验失败则丢弃。这只能发现部分比特错误，不能单独保证可靠，必须与确认、重传配合。

### 2. 序号与确认号

- 序号标识本段数据在字节流中的位置。
- 确认号表示接收方期望收到的下一个字节序号（累积确认的常见语义）。

据此可以检测丢失、重复和乱序，并把乱序段先缓存，等缺口补齐后再按序提交给应用。

### 3. 重传

- **超时重传**：发出数据后在 RTO 内未得到相应确认，则重发。
- **快速重传**：收到重复 ACK 等信号，推断某段丢失，可在定时器到期前重传。

现代 TCP 还有选择确认（SACK）等扩展，便于更精确地重传缺失区间。

### 4. 流量控制

接收方通过窗口字段通告自己还能接收多少字节，发送方不得超出。目的是避免打满对端接收缓冲。

### 5. 拥塞控制

根据丢包、延迟等信号调节发送速率（慢启动、拥塞避免、快重传/快恢复等经典阶段）。目的是减轻网络过载导致的持续丢包，间接支撑可靠传输的效率与稳定性。

## 可以怎么概括回答

```text
差错检测：校验和
丢失/重复/乱序：序号 + ACK + 缓存重排
补齐丢失：重传（超时 / 快速重传等）
接收方能力：滑动窗口流量控制
网络承载：拥塞控制
连接生命周期：三次握手与四次挥手（保证连接起止语义）
```

握手与挥手保证的是连接建立与拆除过程的可靠性约定，数据传输阶段的可靠交付主要靠序号、确认、重传与窗口机制。
